# Misclassification Feedback Model

**Date:** 2026-02-13
**Related Files:** `src/life_organizer/db/models/feedback.py`, `alembic/versions/b4f1c8e23a67_*.py`

## Overview

The misclassification feedback model stores user-submitted corrections when the classifier assigns an input to the wrong category. This is the foundational data layer for the Classification Feedback Loop (Epic 2), enabling correction data to be persisted for future training improvements.

## What Was Built

- `MisclassificationFeedback` ORM model in the `feedback` PostgreSQL schema namespace
- Alembic migration to create the `feedback` schema and `misclassifications` table
- Package export from `life_organizer.db.models`

## Technical Implementation

### Key Files

- `src/life_organizer/db/models/feedback.py`: ORM model definition using SQLAlchemy 2.0 `Mapped[]` + `mapped_column()` pattern
- `alembic/versions/b4f1c8e23a67_create_feedback_schema_and_misclassifications_table.py`: Migration that creates the `feedback` schema and `misclassifications` table
- `src/life_organizer/db/models/__init__.py`: Package-level export for the model
- `tests/db/test_feedback_model.py`: 10 unit tests covering model attributes, metadata, and importability

### Key Patterns

- **Schema Namespace Separation**: The feedback domain uses its own PostgreSQL schema (`feedback`) to separate concerns from the `budget` schema. This is established via `__table_args__ = ({"schema": "feedback"},)` on the model and `CREATE SCHEMA IF NOT EXISTS feedback` in the migration.
- **Model Pattern**: Follows the exact same SQLAlchemy 2.0 pattern as `BudgetTransaction` — `Mapped[]` type annotations with `mapped_column()` for column definitions, `Base` inheritance from `life_organizer.db.base`.

### Code Examples

```python
from life_organizer.db.models import MisclassificationFeedback

# Create a feedback record
feedback = MisclassificationFeedback(
    original_input="Buy groceries",
    wrong_category="note",
    correct_category="budget",
)

# created_at is auto-generated by the database via server_default=func.now()
```

## How to Use

1. Import the model: `from life_organizer.db.models import MisclassificationFeedback`
2. Create instances with required fields: `original_input`, `wrong_category`, `correct_category`
3. The `id` and `created_at` fields are auto-generated (PK auto-increment and server default respectively)

## Configuration

No additional configuration required. The model uses the existing database connection from `life_organizer.db.session`.

| Column | Type | Nullable | Default |
|--------|------|----------|---------|
| `id` | INTEGER (PK) | No | Auto-increment |
| `original_input` | TEXT | No | - |
| `wrong_category` | VARCHAR(50) | No | - |
| `correct_category` | VARCHAR(50) | No | - |
| `created_at` | TIMESTAMP WITH TZ | No | `now()` |

## Notes

- The `feedback` schema is created by the migration — it does not exist on fresh databases until the migration runs
- The migration downgrade drops the entire `feedback` schema with `CASCADE`, removing all tables within it
- Category values are stored as free-text VARCHAR(50), not foreign keys to an enum, allowing flexibility as categories evolve
